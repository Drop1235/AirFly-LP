# 会場販売：セットアップ手順書

会場販売を使い始めるまでに、**あなたにしかできない作業は4つ**です（合計20〜30分ほど）。
上から順番に進めてください。

| # | 作業 | 場所 | 目安 |
|---|---|---|---|
| 1 | Firebaseの「秘密鍵」をダウンロードする | Firebaseコンソール | 3分 |
| 2 | 秘密鍵の中身をNetlifyに登録する | Netlify | 5分 |
| 3 | Firestoreのルールに追記する | Firebaseコンソール | 5分 |
| 4 | GASのコードを貼り替えて再デプロイする | スプレッドシート → Apps Script | 5分 |
| 5 | テスト注文で動作確認する | LP | 10分 |

以下はClaudeが済ませています。
- 機能の実装とテスト、GitHubへのプッシュ、プルリクエストの作成
- スプシのK〜O列の見出し（最初の注文が入ったときにGASが自動で追加します）

## 作業1：Firebaseの「秘密鍵」をダウンロードする

この鍵があると、Netlify（サーバー）がFirestoreに注文を書き込めるようになります。

1. https://console.firebase.google.com/ を開き、プロジェクト **airfly-lp** を選ぶ
2. 左上の **歯車アイコン** →「**プロジェクトの設定**」をクリック
3. 上のタブから「**サービス アカウント**」を選ぶ
4. 「Firebase Admin SDK」の画面で、一番下の「**新しい秘密鍵を生成**」→「**キーを生成**」をクリック
5. `airfly-lp-firebase-adminsdk-xxxxx.json` という名前のファイルがダウンロードされる

> ⚠️ このファイルは**パスワードと同じくらい大事**です。人に送ったり、チャットに貼ったりしないでください。
> 作業2が終わったら削除してOKです（必要になったら、同じ手順でいつでも作り直せます）。

---

## 作業2：秘密鍵の中身をNetlifyに登録する

1. 作業1でダウンロードしたファイルを、**メモ帳**（Windows）や**テキストエディット**（Mac）で開く
   （ダブルクリックで開けない場合は、右クリック →「プログラムから開く」）
2. 中身は次のような形になっています。

   ```
   {
     "type": "service_account",
     "project_id": "airfly-lp",
     ...
     "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEv....(とても長い文字列)....\n-----END PRIVATE KEY-----\n",
     "client_email": "firebase-adminsdk-xxxxx@airfly-lp.iam.gserviceaccount.com",
     ...
   }
   ```

3. https://app.netlify.com/ を開き、AirFlyのサイト（airfly-tm）を選ぶ
4. 左メニューの「**Site configuration**」→「**Environment variables**」→「**Add a variable**」→「**Add a single variable**」
5. 次の2つを、1つずつ登録する

   **1つ目**
   - Key：`FIREBASE_CLIENT_EMAIL`
   - Value：`client_email` の値（`" "` の内側だけ）
     例）`firebase-adminsdk-xxxxx@airfly-lp.iam.gserviceaccount.com`

   **2つ目**
   - Key：`FIREBASE_PRIVATE_KEY`
   - Value：`private_key` の値（`" "` の内側すべて）
     `-----BEGIN PRIVATE KEY-----` から `-----END PRIVATE KEY-----\n` までを、途中の `\n` も含めてそのままコピーする

   - どちらも、Scopes は「All scopes」（または **Functions** にチェックが入った状態）、値は全環境（All deploy contexts）で同じでOKです。

6. 「Create variable」で保存する

> 💡 登録した環境変数は、次にデプロイしたときから有効になります。デプロイは作業5の前にClaudeが行う（またはプルリクエストのマージで自動で行われる）ので、ここで再デプロイする必要はありません。

## 作業3：Firestoreのルールに追記する

「大会情報は誰でも読める」「注文データは管理者だけが読める」というルールを追加します。

1. Firebaseコンソール（airfly-lp）の左メニューで「**Firestore Database**」→ 上のタブ「**ルール**」を開く
2. いま入っているルールを**すべてコピーしてClaudeに送ってください**。そのまま貼り替えられる完成版をお渡しします（いちばん確実な方法です）。

   ご自身で追記する場合は、次の手順で行ってください。
   - 一番最後にある `}` `}` （閉じかっこ2つ）の**直前**に、下の内容を貼り付ける

   ```
       function isVenueAdmin() {
         return request.auth != null && request.auth.token.email == 'hanks@tempmachi.com';
       }

       match /venue_events/{eventId} {
         allow read: if true;
         allow write: if isVenueAdmin();
       }

       match /venue_orders/{orderId} {
         allow read: if isVenueAdmin();
         allow write: if false;
       }
   ```

3. 「**公開**」ボタンを押す

> ⚠️ いまのルールに `match /{document=**}` と `allow read, write: if true` のような「全部許可」の行がある場合、上の制限が効きません。そのときは必ずClaudeにルールを送ってください。

## 作業4：GASのコードを貼り替えて再デプロイする

1. 新しいコードを開く
   https://github.com/Drop1235/AirFly-LP/blob/claude/exciting-maxwell-2j9wac/Code.gs
   右上の「**Copy raw file**」アイコン（四角が2つ重なったアイコン）を押すと、全文がコピーされます。
2. 注文記録用のスプレッドシートを開き、メニューの「**拡張機能**」→「**Apps Script**」
3. 左の「ファイル」から `コード.gs`（または `Code.gs`）を開く
4. 中身をすべて選択（Ctrl+A / ⌘+A）→ 削除 → 1でコピーした内容を貼り付け → 保存（Ctrl+S / ⌘+S）
5. 右上の「**デプロイ**」→「**デプロイを管理**」
6. いま使っているデプロイを選び、右上の**鉛筆アイコン（編集）**をクリック
7. 「バージョン」を「**新バージョン**」に変更 →「**デプロイ**」

> ⚠️ 「新しいデプロイ」ではなく、必ず「**デプロイを管理**」から編集してください。
> 「新しいデプロイ」にするとURLが変わり、Web注文の記録が止まってしまいます。
>
> 💡 貼り付け前のコードに、このリポジトリにない独自の変更を入れていた場合は、上書きすると消えてしまいます。心当たりがあれば、貼り替える前にClaudeに知らせてください。

## 作業5：テスト注文で動作確認する

作業1〜4が終わったら、Claudeに「設定終わった」と伝えてください。Claudeが本番に反映します（プルリクエストをマージすると、Netlifyが自動でデプロイします）。
反映が終わったら、次の流れで確認してください。

1. スマホかPCで `https://airfly-tm.netlify.app/?admin=true` を開き、「管理者メニュー」からログイン
2. 「会場販売（大会）」で、大会名「テスト」、開催日を**今日**にして「大会を登録」
3. 一覧の「URL・QR」でQRコードを表示し、**別のスマホ**で読み取る
4. 帯に「会場限定15%OFF」と出ていることを確認し、商品を選んで「注文を確定（会場でお支払い）」を押す
   → **受付番号（例：A-001）**の画面が出る
5. 管理者側で「受付を開く」→ さっきの注文を選ぶ →「現金」→「ちょうど」→「現金で受領」
6. 次の3点を確認する
   - スプシに1行追加され、K〜O列に「会場: テスト」「A-001」「現金」などが入っている
   - 4で入力したメールアドレスに「ご注文ありがとうございます（会場でのご購入）」が届いている
   - 会場受付の「支払済」タブに、その注文が移っている
7. 確認が終わったら、スプシのテスト行を削除し、管理者メニューでテスト用の大会を「削除」する

うまくいかないときは、画面のスクリーンショットかエラーメッセージをClaudeに送ってください。

## 大会ごとの準備（本番運用）

1. `https://airfly-tm.netlify.app/?admin=true` → 管理者メニュー →「会場販売（大会）」で大会を登録する
   - 2日間開催なら「最終日」も入力する
   - 受付番号の頭文字は大会ごとに変えると区別しやすい（例：A、B…）
2. 「URL・QR」→「印刷用ページ」で印刷し、ブースに掲示する
   - 会場URLは**開催日だけ**有効です。それ以外の日に開くと、通常のWeb販売ページになります。

## 当日の流れ（スタッフ1名）

1. タブレットで `https://airfly-tm.netlify.app/?admin=true` → 管理者メニュー → 大会の「受付を開く」
2. お客様がQRから注文すると、「未払い」に自動で表示される
3. お客様の受付番号の注文を選び、在庫から渡す商品だけ「**手渡し**」に切り替える（送料は自動で計算し直されます）
4. お支払い
   - **現金**：預かり金額を入力 → お釣りを確認 →「現金で受領」
   - **Square**：表示された金額をSquareで決済（メモ欄に受付番号を入力）→「Square決済完了」
5. 支払済にすると、スプシへの記録と、お客様への注文詳細メールが自動で行われる
   - 「要再送」と表示されたときは、「支払済」タブでその注文を開き「再送する」を押す
6. スマホを持っていないお客様には「**代理で注文を入力**」を使う → 入力・確定すると、そのままお会計画面に進む

## 補足（仕組み）

- 未払いの注文はFirestoreにだけ保存され、**スプシには支払済の注文だけ**が記録されます（Web注文と同じ考え方です）。
- 大会期間を過ぎた未払いの注文は確定できず、自動でキャンセル扱いになります。
- 送料：配送の商品が1点でもあれば600円。全商品が手渡しなら0円です。
- 会場では会場限定15%OFFのみで、Webクーポンは使えません。
- スプシのK〜O列：販売チャネル / 受付番号 / 支払方法 / 受取方法 / 入力者
  - D列では、手渡しした商品に【手渡し】が付きます
  - 全商品が手渡しの注文は、J列が「手渡し完了（手配不要）」になり、「LINEで代理店へ送信」の対象から自動で外れます
